# EPAM Interview Study Guide — ShopSpring Backend (Spring Boot)

This guide explains, step by step, what the ShopSpring backend does, which technical concepts it uses, and how each one maps to typical EPAM interview questions.

---

## 1. Project Overview

| Item | Value |
|---|---|
| Type | REST API for an e-commerce catalog (CRUD + search + image upload) |
| Language / JDK | Java 21 |
| Framework | Spring Boot 3.3.3 (Spring MVC, Spring Data JPA) |
| ORM | Hibernate (JPA implementation) |
| Database | MySQL 8 (`ecomdb`), H2 on classpath (not used) |
| Build tool | Maven (`pom.xml`) |
| Utilities | Lombok, Spring Boot DevTools |
| Frontend | React (Vite, port 5173) + Axios |
| Backend port | 8080 |

### Layered architecture

```
React (Axios)  ──HTTP/JSON──►  Controller  ──►  Service  ──►  Repository  ──JDBC──►  MySQL
                               (web layer)     (business)    (data access)
                                   ▲                              ▲
                                   └────────── Entity (Product) ──┘
```

Package structure (`com.cart.ecom_proj`):

- `EcomProjApplication` — entry point.
- `controller.ProductController` — HTTP endpoints.
- `service.ProductService` — business logic.
- `repo.ProductRepo` — data access (Spring Data JPA).
- `model.Product` — JPA entity / domain model.

**Why layers?** Separation of concerns, single responsibility (the **S** in SOLID), testability (each layer can be mocked), replaceability (swap MySQL for Postgres without touching controllers).

## 2. Step-by-Step: What Happens at Startup

1. `main()` calls `SpringApplication.run(EcomProjApplication.class, args)`.
2. `@SpringBootApplication` = `@Configuration` + `@EnableAutoConfiguration` + `@ComponentScan`.
   - **Component scan** searches `com.cart.ecom_proj` and sub-packages for `@RestController`, `@Service`, `@Repository`, etc.
   - **Auto-configuration** inspects the classpath and properties and configures beans automatically: embedded Tomcat, `DispatcherServlet`, Jackson `ObjectMapper`, `DataSource` (HikariCP), `EntityManagerFactory`, transaction manager, multipart resolver.
3. Spring reads `application.properties` (and `application.yml`) — externalized configuration.
4. The `ApplicationContext` is created and beans are instantiated and wired (Dependency Injection).
5. Spring Data JPA creates a **proxy implementation** of `ProductRepo` at runtime (you only wrote an interface).
6. Hibernate connects to MySQL via HikariCP. `ddl-auto` decides whether to touch the schema.
7. Embedded Tomcat starts on port 8080 and `DispatcherServlet` is mapped to `/`.

### Concepts
- **Inversion of Control (IoC)**: the container creates and manages objects, not your code.
- **Dependency Injection (DI)**: dependencies are provided (here with `@Autowired` field injection).
- **Convention over configuration**, **starter dependencies**, **embedded server**.

## 3. Configuration (`application.properties`)

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/ecomdb?createDatabaseIfNotExist=true&useSSL=false&serverTimezone=UTC
spring.datasource.username=root
spring.datasource.password=
spring.jpa.show-sql=true
spring.jpa.hibernate.ddl-auto=none
spring.servlet.multipart.max-file-size=10MB
spring.servlet.multipart.max-request-size=10MB
```

| Property | Meaning |
|---|---|
| `datasource.url` | JDBC connection string. `createDatabaseIfNotExist=true` creates the schema. |
| `show-sql` | Prints SQL generated by Hibernate. |
| `ddl-auto` | `none` / `validate` / `update` / `create` / `create-drop`. With `none`, Hibernate **never changes the schema** — the table must already match the entity. |
| `multipart.max-file-size` | Maximum size of an uploaded file (default is 1MB). |

> **Real bug we hit:** `POST /api/product` returned 500 with `Data truncation`. The `image_date` column in MySQL was too small for the image bytes. Because `ddl-auto=none`, Hibernate did not alter it. Fix: `@Column(columnDefinition = "LONGBLOB")` on the entity **and** `ALTER TABLE product MODIFY image_date LONGBLOB;`.
> Also note: there is an `application.yml` with `ddl-auto: create-drop`, which conflicts with the `.properties` file. Know which one wins and why this is dangerous (`create-drop` deletes data on shutdown).

### Externalizing configuration (interview Q19)
Order of precedence (highest to lowest, simplified): command-line args → OS environment variables → `application-{profile}.properties` → `application.properties`. Tools: `@Value`, `@ConfigurationProperties`, `@Profile`, Spring Cloud Config Server.

### Secret management (VERY IMPORTANT question)
The current project stores the DB password directly in the properties file — **not acceptable in production**. Better options:
- Environment variables: `spring.datasource.password=${DB_PASSWORD}`.
- Kubernetes Secrets (mounted as env vars/files).
- HashiCorp Vault / AWS Secrets Manager / Azure Key Vault (with Spring Cloud Vault).
- CI/CD secret stores (GitHub Actions Secrets, Jenkins credentials).
- Never commit secrets to Git; rotate them; use least-privilege DB users (not `root`); encrypt at rest.

## 4. The Entity: `Product`

```java
@Entity @Data @AllArgsConstructor @NoArgsConstructor
public class Product {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Integer id;
    private String name, description, brand, category;
    private BigDecimal price;
    private LocalDate releaseDate;
    private boolean productAvailable;
    private Integer stockQuantity;
    private String imageName, imageType;
    @Lob @Column(name = "image_date", columnDefinition = "LONGBLOB")
    private byte[] imageDate;
}
```

### Concepts
- **JPA (Jakarta Persistence API)** is the specification; **Hibernate** is the implementation. **ORM** maps Java objects to relational rows.
- `@Entity` — class mapped to a table (`product`). Requires a no-arg constructor.
- `@Id` + `@GeneratedValue(IDENTITY)` — primary key generated by MySQL `AUTO_INCREMENT`. Alternatives: `SEQUENCE`, `TABLE`, `AUTO`.
- **Naming strategy:** Spring Boot's default converts `camelCase` fields to `snake_case` columns (`stockQuantity` → `stock_quantity`, `imageDate` → `image_date`).
- `BigDecimal` for money — never `double`/`float` (binary floating-point precision errors).
- `LocalDate` — Java 8 date/time API, immutable and thread-safe.
- `@Lob` — large object. `byte[]` → BLOB. Default MySQL mapping can be too small; `LONGBLOB` holds up to 4GB.
- **Lombok:** `@Data` generates getters, setters, `equals`, `hashCode`, `toString`; `@NoArgsConstructor`/`@AllArgsConstructor` generate constructors at compile time (annotation processing).
- `@JsonProperty` (Jackson) — controls the JSON field name used in (de)serialization.
- `boolean productAvailable` generates `isProductAvailable()`, which Jackson would name `productAvailable` — hence the explicit annotation.

### Pitfalls to mention in an interview
- Storing images in the DB works but does not scale: prefer object storage (S3/Blob) and save only the URL.
- `@Lob` fields are loaded with every `findAll()` — the list endpoint returns heavy image bytes as Base64 JSON. Solutions: DTOs/projections, `@Basic(fetch = LAZY)`, or a separate image endpoint (which this project already has).
- `@Data` on entities with relationships can cause infinite recursion / bad `hashCode`.
- Entities exposed directly as API responses couple the API to the DB schema — use **DTOs** in larger systems.

## 5. The Repository: `ProductRepo`

```java
@Repository
public interface ProductRepo extends JpaRepository<Product, Integer> {
    @Query("SELECT p FROM Product p WHERE LOWER(p.name) LIKE LOWER(CONCAT('%', :keyword, '%')) OR ...")
    List<Product> searchProducts(String keyword);
}
```

### Concepts
- **Spring Data JPA** generates the implementation at runtime (JDK dynamic proxy → `SimpleJpaRepository`).
- `JpaRepository<T, ID>` gives for free: `findAll`, `findById`, `save`, `deleteById`, `count`, paging/sorting (`findAll(Pageable)`), batch operations.
- `save()` does **insert if the ID is null/new, otherwise merge (update)**. This matters in `updateProduct`.
- `@Query` with **JPQL** — queries the entity model (`Product`, `p.name`), not tables/columns. Contrast with `nativeQuery = true` for raw SQL.
- Named parameter `:keyword` is bound by parameter name (works because Spring Boot compiles with `-parameters`); otherwise use `@Param("keyword")`.
- Parameter binding prevents **SQL injection** (prepared statements).
- `LIKE '%x%'` with a leading wildcard cannot use a normal index → full table scan. For serious search use Full-Text Search / Elasticsearch.
- Alternatives: **derived queries** (`findByNameContainingIgnoreCase`), **Specifications**, **Criteria API**, **Querydsl**.
- `@Repository` also translates persistence exceptions into Spring's `DataAccessException` hierarchy.

## 6. The Service: `ProductService`

```java
@Service
public class ProductService {
    @Autowired private ProductRepo repo;
    ...
}
```

Methods:

| Method | What it does |
|---|---|
| `getAllProducts()` | `repo.findAll()` → `SELECT * FROM product` |
| `getProductById(id)` | `repo.findById(id).orElse(null)` (`Optional` unwrapping) |
| `addProduct(product, file)` | Copies file name, content type and bytes into the entity, then `repo.save` |
| `updateProduct(id, product, file)` | Same as add, then `save` (**note:** the `id` argument is not set on `product`; it relies on the client sending the id in the JSON. Better: `product.setId(id)` or load the existing one) |
| `deleteProduct(id)` | `repo.deleteById(id)` |
| `searchProducts(keyword)` | Delegates to the JPQL query |

### Concepts
- `@Service` is a stereotype of `@Component` — a Spring-managed singleton bean holding business logic.
- **Singleton scope** (default): one instance per `ApplicationContext`; must be stateless/thread-safe.
- **`Optional<T>`** avoids null pointer errors. Returning `orElse(null)` is acceptable here but `orElseThrow(...)` with a custom exception is more idiomatic.
- `MultipartFile` (`getBytes()`, `getOriginalFilename()`, `getContentType()`) — Spring's abstraction of an uploaded file. `getBytes()` loads the whole file in memory (OK for ≤10MB; stream for big files).
- **Checked exception** `IOException` is propagated up.
- **`@Transactional`:** not used explicitly here. `SimpleJpaRepository` methods are already transactional (`save`, `deleteById` are `@Transactional`; reads are `readOnly = true`). If a service method performed multiple repository operations that must succeed or fail together, you would annotate it with `@Transactional`.

### `@Transactional` internals (interview Q13)
- Spring creates an **AOP proxy** (CGLIB or JDK) around the bean. The proxy opens a transaction via `PlatformTransactionManager` (here `JpaTransactionManager`), calls the method, commits on success, rolls back on **unchecked exceptions** (RuntimeException/Error) by default — not on checked ones unless `rollbackFor` is set.
- **Self-invocation pitfall:** calling a `@Transactional` method from another method in the same class bypasses the proxy.
- **Propagation:** `REQUIRED` (default), `REQUIRES_NEW`, `SUPPORTS`, `NOT_SUPPORTED`, `MANDATORY`, `NEVER`, `NESTED`.
- **Isolation:** `READ_UNCOMMITTED`, `READ_COMMITTED`, `REPEATABLE_READ` (MySQL InnoDB default), `SERIALIZABLE`; prevent dirty reads, non-repeatable reads, phantom reads respectively.
- Persistence context (first-level cache), dirty checking and flush happen within the transaction.

## 7. The Controller: `ProductController`

Class-level annotations:
- `@RestController` = `@Controller` + `@ResponseBody` → return values are serialized to JSON by Jackson (`HttpMessageConverter`).
- `@RequestMapping("/api")` — base path.
- `@CrossOrigin` — enables **CORS** so the React dev server (`localhost:5173`) can call `localhost:8080`. Without it, the browser blocks the response (Same-Origin Policy). Production: restrict origins (`@CrossOrigin(origins = "...")` or global `WebMvcConfigurer`) — never wildcard with credentials.

### Endpoints

| HTTP | Path | Handler | Success | Failure |
|---|---|---|---|---|
| GET | `/api/products` | `getAllProducts` | 200 + list | — |
| GET | `/api/product/{id}` | `getProduct` | 200 + product | 404 |
| POST | `/api/product` | `addProduct` (multipart) | 201 + saved product | 500 + message |
| GET | `/api/product/{productId}/image` | `getImageByProductId` | 200 + bytes with the stored content type | 404 |
| PUT | `/api/product/{id}` | `updateProduct` (multipart) | 200 "Updated" | 400 |
| DELETE | `/api/product/{id}` | `deleteProduct` | 200 "Deleted" | 404 |
| GET | `/api/products/search?keyword=` | `searchProducts` | 200 + list | — |

### Annotations used
- `@GetMapping/@PostMapping/@PutMapping/@DeleteMapping` — shortcuts for `@RequestMapping(method = ...)`.
- `@PathVariable` — value from the URL path.
- `@RequestParam` — query string parameter (required by default).
- `@RequestPart` — one part of a `multipart/form-data` request. `Product` is deserialized from a JSON part (needs part `Content-Type: application/json`); `MultipartFile` from the file part.
- `ResponseEntity<T>` — full control of status code, headers and body.
- `HttpStatus` — `OK`, `CREATED`, `NOT_FOUND`, `BAD_REQUEST`, `INTERNAL_SERVER_ERROR`.

### REST principles
- Resource-oriented URLs, HTTP verbs map to CRUD, stateless server, proper status codes.
- Idempotency: `GET`, `PUT`, `DELETE` are idempotent; `POST` is not.
- Observations to discuss: the paths mix singular/plural (`/product`, `/products`); `POST` should return a `Location` header; `PUT` swallows the `IOException` into a `RuntimeException` (better to use `@ControllerAdvice`).

### Code smells you should be able to point out (shows seniority)
1. **Field injection (`@Autowired` on a field)** → prefer **constructor injection** (immutability, testability, required dependencies explicit, no reflection needed in tests). With a single constructor, `@Autowired` is optional.
2. `System.out.println` → use SLF4J logger (`private static final Logger log = LoggerFactory.getLogger(...)`).
3. `catch (Exception e)` returning the exception message to the client leaks internals → use a global `@RestControllerAdvice` + `@ExceptionHandler` and return a structured error (`ProblemDetail`, RFC 7807).
4. No validation → add `jakarta.validation` (`@Valid`, `@NotBlank`, `@Positive`) and `spring-boot-starter-validation`.
5. Entity used directly as request/response → use DTOs (+ MapStruct).
6. No pagination in `findAll()` → `Pageable`.
7. `updateProduct` ignores the `id` path variable and requires the image on every update.
8. No security (no authentication/authorization) → Spring Security + JWT/OAuth2.
9. Root DB user with an empty password.
10. `H2` dependency present but unused; `application.yml` and `application.properties` conflict.

## 8. End-to-End Request Flows

### 8.1 Add product (`POST /api/product`) — the most important flow

1. **React `AddProduct.jsx`** builds a `FormData`:
   - part `imageFile` → the selected file,
   - part `product` → `new Blob([JSON.stringify(product)], { type: "application/json" })`.
   Axios sends `multipart/form-data` to `http://localhost:8080/api/product`.
2. **Browser CORS**: for cross-origin requests with non-simple content types the browser may send a preflight `OPTIONS`; `@CrossOrigin` makes Spring answer with `Access-Control-Allow-Origin`.
3. **Tomcat** receives the request and hands it to the **`DispatcherServlet`** (front controller pattern).
4. `MultipartResolver` parses the body; size limits (10MB) are checked.
5. **`HandlerMapping`** finds `ProductController.addProduct` (`POST /api/product`).
6. **`HandlerAdapter` + argument resolvers**: `RequestPartMethodArgumentResolver` converts the `product` part to a `Product` using Jackson (`MappingJackson2HttpMessageConverter`) and binds `imageFile` as `MultipartFile`.
7. Controller calls `service.addProduct(product, imageFile)`.
8. Service sets `imageName`, `imageType`, `imageDate` (bytes) and calls `repo.save(product)`.
9. `SimpleJpaRepository.save` (`@Transactional`): `id == null` → `em.persist()`.
10. Hibernate generates `INSERT INTO product (brand, category, description, image_date, image_name, image_type, name, price, product_available, release_date, stock_quantity) VALUES (?,?,...)`. `IDENTITY` forces an immediate insert to obtain the generated id.
11. JDBC (via HikariCP connection) executes it on MySQL; the transaction commits.
12. The saved entity (now with an id) returns up to the controller → `ResponseEntity` 201 CREATED → Jackson serializes to JSON (the `byte[]` becomes Base64) → React `.then()`.
13. If MySQL throws (e.g. *Data truncation*), Hibernate throws `JDBCException` → Spring wraps it in `DataIntegrityViolationException` → the controller's `catch` returns **500 + message**. That is exactly the error seen in the browser console.

### 8.2 Get all products (`GET /api/products`)
Controller → `service.getAllProducts()` → `repo.findAll()` → `SELECT ... FROM product` → list of entities → Jackson → JSON array. Image bytes are included (heavy).

### 8.3 Get product image (`GET /api/product/{id}/image`)
Loads the entity, returns raw `byte[]` with `Content-Type` from `imageType` (e.g. `image/jpeg`) so the browser can render it in `<img src="...">`. 404 if no product/image.

### 8.4 Search (`GET /api/products/search?keyword=phone`)
`@RequestParam` → service → JPQL → Hibernate translates to `WHERE lower(name) like lower(concat('%',?,'%')) OR ...` with a bound parameter.

### 8.5 Update (`PUT /api/product/{id}`)
Multipart again → service sets the new image → `save()` → because the entity has an id, Hibernate does `select` + `update` (merge).

### 8.6 Delete (`DELETE /api/product/{id}`)
Controller checks existence → `deleteById` → `DELETE FROM product WHERE id=?`.

## 9. Spring Concepts — Theory + Interview Answers

### 9.1 Spring Bean lifecycle (Q11)
1. Instantiation (constructor). 2. Populate properties / dependency injection. 3. `BeanNameAware`, `BeanFactoryAware`, `ApplicationContextAware` callbacks. 4. `BeanPostProcessor.postProcessBeforeInitialization`. 5. `@PostConstruct` → `InitializingBean.afterPropertiesSet()` → custom `init-method`. 6. `postProcessAfterInitialization` (AOP proxies are created here). 7. Bean ready. 8. On shutdown: `@PreDestroy` → `DisposableBean.destroy()` → custom destroy method.

### 9.2 `@Autowired` vs `@Inject` (Q12)
`@Autowired` is Spring-specific (has `required` attribute). `@Inject` is the JSR-330 standard (`jakarta.inject`), no `required` (use `Optional`/`@Nullable`). Behavior is almost identical; both are resolved by `AutowiredAnnotationBeanPostProcessor`: by **type**, then qualifier/name (`@Qualifier` / `@Named`, `@Primary`).

### 9.3 Dependency injection types
Constructor (recommended), setter (optional dependencies), field (avoid). Spring uses **reflection** (`Constructor.newInstance`, `Field.set` with `setAccessible(true)`) in `BeanPostProcessor`s to inject (Q17).

### 9.4 Spring Boot Starters (Q14)
Curated dependency descriptors: `spring-boot-starter-web` (Spring MVC + Tomcat + Jackson), `spring-boot-starter-data-jpa` (Hibernate + Spring Data + HikariCP), `spring-boot-starter-test` (JUnit 5, Mockito, AssertJ), etc. Versions are managed by `spring-boot-starter-parent` BOM.

### 9.5 Auto-configuration
`@EnableAutoConfiguration` loads classes listed in `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`, applied conditionally (`@ConditionalOnClass`, `@ConditionalOnMissingBean`, `@ConditionalOnProperty`). Debug with `--debug` or the Actuator `conditions` endpoint.

### 9.6 `ApplicationContext` vs `BeanFactory` (Q16)
`BeanFactory` = basic container, lazy initialization. `ApplicationContext` extends it: eager singleton init, events, i18n (`MessageSource`), resource loading, environment/profiles, AOP integration. Always use `ApplicationContext`.

### 9.7 Custom annotations (Q15)
Define with `@Target`, `@Retention(RUNTIME)`, optionally meta-annotate (`@Component`, `@Constraint`), and process with AOP (`@Aspect` + `@Around`), a `BeanPostProcessor`, or a `ConstraintValidator`.

### 9.8 `CommandLineRunner` / `ApplicationRunner` (Q18)
Beans executed after the context starts (seed data, startup checks). `ApplicationRunner` receives parsed `ApplicationArguments`; `CommandLineRunner` gets raw `String[]`. Order with `@Order`.

### 9.9 Actuator (Q20)
`spring-boot-starter-actuator`: `/actuator/health`, `/info`, `/metrics`, `/env`, `/beans`, `/mappings`, `/loggers`, `/prometheus`, `/threaddump`, `/heapdump`. Used for liveness/readiness probes in Kubernetes. Secure it and expose only necessary endpoints.

### 9.10 Spring MVC request flow (summary)
Client → Servlet container → Filters → `DispatcherServlet` → `HandlerMapping` → Interceptors (`preHandle`) → Controller → `HttpMessageConverter` (JSON) → Interceptors (`postHandle/afterCompletion`) → Response.

### 9.11 Exception handling (what this project should add)
```java
@RestControllerAdvice
public class GlobalExceptionHandler {
    @ExceptionHandler(DataIntegrityViolationException.class)
    public ResponseEntity<ProblemDetail> handle(DataIntegrityViolationException ex) { ... }
}
```

### 9.12 Profiles
`application-dev.properties`, `application-prod.properties`, activated with `spring.profiles.active=prod` — different DB, logging, `ddl-auto`.

### 9.13 Production database practice
Do not use `ddl-auto=update/create` in production; use **Flyway/Liquibase** migrations (versioned SQL). This would have prevented the `Data truncation` problem.

### 9.14 Hibernate concepts
- **Persistence context** (first-level cache), entity states: transient → managed → detached → removed.
- **Dirty checking**, flush modes.
- **Lazy vs eager** loading, **N+1 problem** (fix: `JOIN FETCH`, `@EntityGraph`, batch size).
- **Second-level cache**, optimistic locking (`@Version`) vs pessimistic locking.
- **HikariCP**: connection pooling (default pool size 10).

|---|---|

### SOLID mapped to this project
- **S**: Controller/Service/Repo each have one responsibility.
- **O**: Add new queries/behaviors by extending the repo/service without modifying existing code.
- **L**: Any `ProductRepo` implementation (real, mock) is substitutable.
- **I**: Small, focused repository interface (could be split into read/write).
- **D**: Controller depends on the service abstraction/Spring-provided beans, not on `new`.

### HashMap / concurrency hooks (likely follow-ups)
- Spring singletons are shared across threads → services must be stateless. Tomcat uses a thread pool (default 200 threads) → each request runs in its own thread.
- Spring's bean registry uses `ConcurrentHashMap`. Know: HashMap internals (array of buckets, hash → index, linked list → red-black tree at 8 entries, resize at load factor 0.75 doubling capacity); `ConcurrentHashMap` uses CAS + per-bin `synchronized` (Java 8+) vs `Collections.synchronizedMap` locking the whole map.
- Java 21: **virtual threads** (`spring.threads.virtual.enabled=true` in Boot 3.2+).

## 11. Microservices & Infrastructure Topics (Related to Your List)

How this monolith could evolve:

- **API Gateway** (Spring Cloud Gateway / Kong / AWS API Gateway): single entry point; routing, authentication, rate limiting, TLS termination, request aggregation, CORS centralization, logging. Frontend calls the gateway instead of each service.
- **Service discovery** (Eureka/Consul): services register themselves; clients/gateway resolve logical names (`lb://product-service`) via client-side load balancing.
- **Config Server**: centralized, versioned configuration (Git-backed), refreshed with `/actuator/refresh` or Spring Cloud Bus.
- **Communication**: synchronous REST/gRPC (OpenFeign, `RestClient`/`WebClient`), asynchronous messaging (Kafka/RabbitMQ) for events like `ProductCreated`.
- **Resilience (Resilience4j)**: Circuit Breaker (closed → open → half-open), Retry with backoff, Rate Limiter, Bulkhead, Timeout.
- **Distributed transactions**: Saga (choreography or orchestration with compensating actions), Outbox pattern; 2PC is rarely used in microservices.
- **Security**: OAuth2 / OpenID Connect with an Authorization Server (Keycloak); JWT validated by resource servers (`spring-boot-starter-oauth2-resource-server`); scopes/roles; service-to-service with client credentials / mTLS.
- **Observability**: Micrometer + Prometheus + Grafana (metrics), ELK/Loki (logs with correlation ids), **distributed tracing** with OpenTelemetry / Zipkin (Sleuth was replaced by Micrometer Tracing in Boot 3).
- **Challenges**: data consistency, network failures, versioning, debugging, deployment complexity, eventual consistency.

### Deployment process (VERY IMPORTANT question) — how to deploy this app
1. **Build**: `mvn clean package` → executable fat JAR (`spring-boot-maven-plugin`).
2. **Test** in CI (unit with JUnit/Mockito, `@WebMvcTest`, `@DataJpaTest`, integration with **Testcontainers** MySQL).
3. **Dockerize**:
   ```dockerfile
   FROM eclipse-temurin:21-jre
   COPY target/ecom-proj-0.0.1-SNAPSHOT.jar app.jar
   ENTRYPOINT ["java","-jar","/app.jar"]
   ```
4. **CI/CD pipeline** (GitHub Actions/Jenkins/GitLab): checkout → build → test → static analysis (SonarQube) → build and push the image to a registry → deploy.
5. **Deploy** to Kubernetes (Deployment, Service, Ingress, ConfigMap, Secret, HPA) or cloud services (AWS ECS/Beanstalk, Azure App Service).
6. **Config & secrets** injected through environment variables / secret managers; profile `prod`.
7. **DB migrations** by Flyway/Liquibase.
8. **Strategies**: rolling update, blue-green, canary; health checks (`/actuator/health/liveness|readiness`); rollback.
9. **Monitoring** and alerting after release.

### 12.5 LRU Cache
```java
class LRUCache<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;
    LRUCache(int capacity) { super(capacity, 0.75f, true); this.capacity = capacity; }
```

### 12.6 Simple rate limiter (fixed window)
```java
class RateLimiter {
    private final int max; private final long windowMs;
    private final Map<String, Deque<Long>> hits = new ConcurrentHashMap<>();
    RateLimiter(int max, long windowMs) { this.max = max; this.windowMs = windowMs; }
    boolean allow(String key) {
        long now = System.currentTimeMillis();
        Deque<Long> q = hits.computeIfAbsent(key, k -> new ArrayDeque<>());
        synchronized (q) {
            while (!q.isEmpty() && now - q.peekFirst() > windowMs) q.pollFirst();
            if (q.size() < max) { q.addLast(now); return true; }
            return false;
        }
    }
}
```
Mention alternatives: token bucket, leaky bucket, sliding window; in production use Redis, Bucket4j or Resilience4j, or the API gateway.

## 16. Core Java Deep Questions (Q1–Q10 of your list)

**Q1. SOLID** — S: one reason to change (Controller/Service/Repo). O: open for extension, closed for modification (strategy/polymorphism instead of `if/else` chains). L: subtypes must be usable wherever the parent is (a `Square` extending `Rectangle` that breaks `setWidth` violates it). I: many small interfaces rather than one fat one. D: depend on abstractions; Spring injects them.

**Q2. Abstraction vs Encapsulation** — Abstraction hides *complexity* (what, via interface/abstract class: `JpaRepository.save()` — you don't see the SQL). Encapsulation hides *data* (how, via private fields + controlled access: `Product` private fields with getters/setters; `ATM` PIN validation).

**Q3. Immutable class** — `final` class; `private final` fields; no setters; constructor sets everything; defensive copies of mutable inputs *and* outputs (`new ArrayList<>(list)`, `Collections.unmodifiableList`, `date.clone()`). Or a Java 16+ `record`. Benefits: thread-safe, cacheable, safe as map keys. Example: `String`, `BigDecimal`, `LocalDate`.
```java
public final class Money {
    private final BigDecimal amount; private final String currency;
    public Money(BigDecimal a, String c) { this.amount = a; this.currency = c; }
    public BigDecimal getAmount() { return amount; }
    public String getCurrency() { return currency; }
}
```

**Q4. HashMap internals** — Array of buckets (`Node<K,V>[]`, default capacity 16, load factor 0.75). `put`: `hash = h ^ (h >>> 16)`; index = `(n-1) & hash`; empty → new node; else compare `hash` then `equals()`; same key → replace value; else append to the linked list. List length ≥ 8 and table ≥ 64 → converted to a **red-black tree** (O(log n)); back to a list at ≤ 6. **Resize** when `size > capacity * 0.75`: new array of double size, entries redistributed (each stays at the same index or moves by `oldCapacity` — one bit decides). Null key allowed (bucket 0). Not thread-safe (concurrent resize can lose data; Java 7 could loop infinitely). Always override `equals` and `hashCode` together, and use immutable keys.

**Q5. ConcurrentHashMap vs `Collections.synchronizedMap`** — synchronizedMap wraps every method with one mutex (whole map locked; iteration needs manual synchronization; throws `ConcurrentModificationException`). `ConcurrentHashMap` (Java 8+): lock-free reads, CAS on empty bins, `synchronized` only on the first node of a bin; weakly-consistent iterators (no CME); atomic ops (`putIfAbsent`, `computeIfAbsent`, `merge`); no null keys/values.

**Q6. Thread lifecycle** — NEW → RUNNABLE → (BLOCKED | WAITING | TIMED_WAITING) → TERMINATED. `start()` creates a new thread of execution and calls `run()` on it; calling `run()` directly just executes it as a normal method on the *current* thread. `start()` twice → `IllegalThreadStateException`.

**Q7. ExecutorService vs ForkJoinPool** — `ExecutorService` (e.g. `Executors.newFixedThreadPool`): general task pool with a shared queue; good for independent, blocking/IO tasks. `ForkJoinPool`: divide-and-conquer (`RecursiveTask`), **work-stealing** (each worker has its own deque, idle workers steal) – good for CPU-bound recursive tasks; used by parallel streams and `CompletableFuture` default. Java 21: virtual threads (`Executors.newVirtualThreadPerTaskExecutor()`) for blocking IO.

**Q8. Comparable vs Comparator** — `Comparable<T>`: natural order inside the class (`compareTo`), one only. `Comparator<T>`: external, multiple orderings.
```java
list.sort(Comparator.comparing(Employee::getSalary).reversed().thenComparing(Employee::getName));
```

**Q9. Java Memory Model & `volatile`** — JMM defines visibility and ordering between threads (happens-before). `volatile`: every read sees the latest write (no thread-local caching), prevents instruction reordering around it; **does not give atomicity** (`count++` still races → use `AtomicInteger`/`synchronized`). Happens-before: unlock→lock of same monitor, volatile write→read, `Thread.start()`, `join()`. Classic use: stop flag, double-checked locking singleton.

**Q10. Memory leaks** — Causes: static collections that keep growing, unclosed resources (streams, connections), listeners/callbacks not removed, `ThreadLocal` in thread pools without `remove()`, bad `equals/hashCode` keys in caches, inner classes holding outer references. Tools: heap dump (`jmap`, `-XX:+HeapDumpOnOutOfMemoryError`), VisualVM, Eclipse MAT, JFR; fixes: try-with-resources, `WeakHashMap`/bounded caches (Caffeine), clean listeners. In Spring: Actuator `/heapdump`, Micrometer JVM metrics.

## 17. Core Java Rapid-Fire (Technical Round)

| Question | Answer |
|---|---|
| `final`, `finally`, `finalize` | `final`: constant variable / non-overridable method / non-inheritable class. `finally`: block that runs after try/catch (except `System.exit` or JVM crash). `finalize()`: deprecated GC hook, never use (use try-with-resources / `Cleaner`). |
| Pass by value or reference? | **Always pass by value.** For objects, the *reference* is copied: you can mutate the object through it, but reassigning the parameter doesn't affect the caller. Proof: `void change(StringBuilder s){ s.append("x"); s = new StringBuilder("y"); }` → caller sees only the `"x"` append. |
| `static` | Belongs to the class, not instances; loaded once; static methods can't access instance members or `this`; static blocks run at class loading. |
| String Pool | Area in the heap where string **literals** are interned and reused. `"a" == "a"` is true; `new String("a") == "a"` is false; `intern()` returns the pooled one. Strings are immutable → safe to share, hash cached. |
| `@Override` | Compile-time check that the method really overrides a parent method. Without it, a typo (`equal` vs `equals`) silently creates a new overload and the bug appears at runtime. |
| Overload `main`? | Yes, but the JVM only calls `public static void main(String[] args)`. |
| Constructors | Initialize objects; same name as the class, no return type. Types: default, no-arg, parameterized, copy (user-defined). Can be overloaded, chained with `this()`/`super()`, not inherited. |
| 4 OOP pillars | Encapsulation (`Product` private fields), Inheritance (`ElectronicProduct extends Product`), Polymorphism (`List<Product>` with overriden `toString`), Abstraction (interfaces). |
| Compile-time vs runtime polymorphism | Compile-time = **overloading** (resolved by the compiler from signatures). Runtime = **overriding** (dynamic dispatch via the actual object type: `Animal a = new Dog(); a.sound();` → Dog's). |
| Abstract class vs interface | Abstract: state (fields), constructors, partial implementation, single inheritance; "is-a" base. Interface: contract, multiple implementation, default/static methods (Java 8), no instance state; "can-do" capability. Prefer interfaces; abstract class for shared state/code. |
| Shallow vs deep copy | Shallow copies references (shared nested objects, e.g. `clone()` default); deep copies the entire graph. Implement through copy constructors, serialization, or recursively cloning. |
| HashMap vs Hashtable | HashMap: unsynchronized, allows one null key/null values, faster. Hashtable: legacy, synchronized, no nulls. Use `ConcurrentHashMap`. |
| ArrayList vs Vector | ArrayList: unsynchronized, grows ×1.5. Vector: synchronized legacy, grows ×2. |
| Quicksort | Pick pivot, partition (smaller left / larger right), recurse. Avg O(n log n), worst O(n²) (sorted input with bad pivot), space O(log n), in-place, not stable. |
| Quicksort vs Merge sort | Merge: always O(n log n), stable, O(n) extra space, good for linked lists/external sort. Quick: faster in practice (cache-friendly), in-place. Java: `Arrays.sort(int[])` = dual-pivot quicksort; objects = TimSort (stable). |
| Synchronized block | Acquires the intrinsic **monitor lock** of the given object; one thread at a time; releases on exit/exception; provides visibility (happens-before). `synchronized(this)` vs method-level vs `static synchronized` (class lock). `ReentrantLock` offers tryLock, fairness, conditions. |
| Requirement traceability matrix | Table linking requirements → design → code → test cases, ensuring every requirement is implemented and tested. |

### Code: Binary search
```java
static int binarySearch(int[] a, int target) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;      // avoids overflow
        if (a[mid] == target) return mid;
        if (a[mid] < target) lo = mid + 1; else hi = mid - 1;
    }
    return -1;
}   // O(log n), O(1)
```

### Code: Stack using an array

```java
class ArrayStack {

    ArrayStack(int cap) { data = new int[cap]; }
    void push(int x) { if (top == data.length - 1) throw new IllegalStateException("full"); data[++top] = x; }
    int pop()  { if (top < 0) throw new IllegalStateException("empty"); return data[top--]; }
    int peek() { if (top < 0) throw new IllegalStateException("empty"); return data[top]; }
    boolean isEmpty() { return top < 0; }
}
```

### Producer–Consumer (`wait`/`notify`)
```java
class Buffer {
    private final Queue<Integer> q = new LinkedList<>(); private final int cap = 5;
    synchronized void produce(int v) throws InterruptedException {
        while (q.size() == cap) wait();        // always a while loop (spurious wakeups)
        q.add(v); notifyAll();
    }
    synchronized int consume() throws InterruptedException {
        while (q.isEmpty()) wait();
        int v = q.poll(); notifyAll(); return v;
    }
}
```

### Second highest number — O(n), O(1)

```java
static int secondHighest(int[] a) {

    for (int x : a) {
        if (x > max) { second = max; max = x; }

}
```

### Reverse linked list
```java
// iterative O(n) O(1)
Node reverse(Node head) {
    Node prev = null, cur = head;
    while (cur != null) { Node next = cur.next; cur.next = prev; prev = cur; cur = next; }
    return prev;
}
// recursive O(n) O(n) stack
Node reverseRec(Node head) {
    if (head == null || head.next == null) return head;
    Node newHead = reverseRec(head.next);
    head.next.next = head; head.next = null;
    return newHead;
}
```

### Rotate image 90° clockwise (in place)
```java
void rotate(int[][] m) {
    int n = m.length;
    for (int i = 0; i < n; i++) for (int j = i + 1; j < n; j++) { int t = m[i][j]; m[i][j] = m[j][i]; m[j][i] = t; } // transpose
    for (int[] row : m) for (int i = 0, j = n - 1; i < j; i++, j--) { int t = row[i]; row[i] = row[j]; row[j] = t; }   // reverse rows
}   // O(n²), O(1)
```

### Trapping Rain Water — two pointers O(n) O(1)
```java
int trap(int[] h) {
    int l = 0, r = h.length - 1, lmax = 0, rmax = 0, water = 0;
    while (l < r) {
        if (h[l] < h[r]) { lmax = Math.max(lmax, h[l]); water += lmax - h[l++]; }
        else             { rmax = Math.max(rmax, h[r]); water += rmax - h[r--]; }
    }
    return water;
}
```

### Top view of a binary tree (BFS + horizontal distance)
```java
List<Integer> topView(TreeNode root) {
    Map<Integer, Integer> m = new TreeMap<>(); Queue<Object[]> q = new LinkedList<>();
    q.add(new Object[]{root, 0});
    while (!q.isEmpty()) {
        Object[] cur = q.poll(); TreeNode n = (TreeNode) cur[0]; int hd = (int) cur[1];
        m.putIfAbsent(hd, n.val);               // first node seen at each HD
        if (n.left != null)  q.add(new Object[]{n.left, hd - 1});
        if (n.right != null) q.add(new Object[]{n.right, hd + 1});
    }
    return new ArrayList<>(m.values());
}
```
